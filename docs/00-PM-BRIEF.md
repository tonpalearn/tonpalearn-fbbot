# PM Brief — FB Page Chatbot (TONPALEARN)

> เอกสารตั้งต้นจาก PM ถึงทีม · ทุกคนต้องอ่านก่อนเริ่ม · ข้อเคาะในนี้ถือเป็น **ของจริง** ห้ามเปลี่ยนเองโดยไม่ถามต้น
> วันที่เคาะ: 5 สิงหาคม 2569 (2026-08-05)

## 1. โจทย์ในหนึ่งย่อหน้า
เพจ TONPALEARN มีคนทักเข้ามาถามซ้ำ ๆ เรื่องเดิม (คอร์สนี้สอนอะไร ราคาเท่าไร วันไหน จองยังไง รับสอนในองค์กรไหม)
ต้นตอบเองไม่ทันและตอบช้าตอนสอน/เดินทาง คนที่สนใจจริงหลุดมือ
ต้องการบอตที่ตอบแทนได้ทันทีตลอด 24 ชั่วโมง เก็บชื่อ-เบอร์-ความสนใจไว้ให้ และรู้จัก **ยกหูส่งต่อให้คนจริง** เมื่อเกินความสามารถ

## 2. ข้อเคาะที่ล็อกแล้ว
| หัวข้อ | ที่เคาะ |
|---|---|
| เพจตั้งต้น | TONPALEARN (สอน AI) |
| สมองบอต | **Hybrid** — กติกา (คำสำคัญ + ปุ่ม) มาก่อน → ถ้าไม่ตรง ใช้ AI (Claude) + ฐานความรู้ (RAG) |
| ขอบเขต MVP | ① ตอบแชท + FAQ/ฐานความรู้ ② เก็บ Lead + ส่งต่อ ③ Human Handoff (โอนหาคน) |
| สแตก | Next.js (App Router) + Supabase (Postgres + pgvector) + Vercel |
| โมเดล | Claude (ตระกูล Claude 5) ผ่าน Anthropic API |
| ภาษา | ไทยเป็นหลัก, รองรับอังกฤษแบบตอบได้ |

## 3. นอกขอบเขต MVP (Non-Goals) พร้อมเหตุผล
1. **ตอบคอมเมนต์ใต้โพสต์อัตโนมัติ** — ต้องขอสิทธิ์ `pages_manage_engagement` เพิ่มและเสี่ยงตอบพลาดต่อสาธารณะ → เฟส 2
2. **Multi-Page SaaS ขายต่อ** — ออกแบบฐานข้อมูลให้มี `page_id` แยกไว้แล้ว แต่ไม่สร้างระบบสมาชิก/บิลในรอบนี้
3. **รับชำระเงินในแชท** — ยังใช้ลิงก์ไปหน้า /booking ของ tonpalearn.com เหมือนเดิม
4. **เสียง/รูปภาพขาเข้า (วิเคราะห์ภาพที่ลูกค้าส่ง)** — ต้นทุนและความซับซ้อนไม่คุ้มกับปริมาณตอนนี้
5. **แปลหลายภาษาอัตโนมัติ** — ลูกค้าจริงเกือบทั้งหมดเป็นคนไทย

## 5. นิยามคำว่า "เสร็จ" (Definition of Done) ของทั้งโปรเจกต์
- [ ] `npm run build` ผ่าน และ `npm test` เขียว
- [ ] webhook ยืนยันกับ Facebook ผ่าน (GET challenge) และตรวจลายเซ็น `X-Hub-Signature-256` จริง
- [ ] ส่งข้อความทดสอบเข้าเพจแล้วบอตตอบกลับได้จริง (มีหลักฐานเป็น log/ภาพ)
- [ ] หน้าแอดมินเปิดได้ ล็อกอินได้ แก้ FAQ แล้วบอตตอบตามที่แก้
- [ ] โอนหาคนแล้วบอตเงียบจริง และคืนสายกลับได้
- [ ] `docs/SPEC.md` + `docs/PRD.html` ตรงกับโค้ดที่ส่ง
- [ ] มีเอกสาร `docs/DEPLOY.md` ที่คนอื่นทำตามแล้วขึ้นได้เอง
- [ ] ผ่าน red-team ของ `lucifer` และแก้ประเด็นระดับ blocker ครบ

## 6. ความเสี่ยงที่รู้ล่วงหน้า
| ความเสี่ยง | ผลกระทบ | ทางรับมือ |
|---|---|---|
| Facebook App Review ไม่ผ่าน/ช้า | ขึ้นใช้จริงกับคนนอกไม่ได้ | รอบแรกรันในโหมด Development + ใส่ผู้ทดสอบเป็น admin เพจ ใช้งานจริงได้ทันทีในวงจำกัด |
| บอตตอบมั่ว (hallucination) | เสียความน่าเชื่อถือ/ให้ข้อมูลราคาผิด | ราคา-วันอบรมมาจากฐานข้อมูลเท่านั้น ห้ามให้โมเดลแต่งตัวเลข + ตอบ "ไม่แน่ใจ ขอส่งต่อให้ทีม" เมื่อความมั่นใจต่ำ |
| หน้าต่าง 24 ชั่วโมงปิด | ส่งข้อความตามไม่ได้ | บันทึกเวลาข้อความล่าสุด และเตือนแอดมินในหน้า inbox |
| ค่าโมเดลบานปลาย | ต้นทุนต่อเดือนเกินคาด | กติกาก่อน AI, จำกัดความยาว, cache คำตอบซ้ำ, มีเพดานต่อวัน |
| ข้อมูลส่วนบุคคลรั่ว | ผิด PDPA | เปิด RLS ทุกตาราง, ไม่ log ข้อความเต็ม, ข้อความแจ้งเก็บข้อมูลตอนขอเบอร์ |

## 7. เฟสการส่งมอบ
- **เฟส 0 (วันนี้)** — spec + PRD.html + mock screen ✅ ต้องได้ก่อนเขียนโค้ด
- **เฟส 1** — webhook + สมองไฮบริด + FAQ + เก็บ lead + handoff + หน้าแอดมิน → พร้อม deploy
- **เฟส 2 (ยังไม่ทำ)** — ตอบคอมเมนต์ใต้โพสต์, broadcast, วิเคราะห์สถิติเชิงลึก, multi-page
