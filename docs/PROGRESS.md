## บันทึกจากการ deploy จริง (7 ส.ค. 2569)
- อาการเด้ง 404 หลังล็อกอิน = หน้า `/admin` เป็น static ถูกแคชที่ CDN → แก้ด้วย `force-dynamic` + โหลดหน้าใหม่ทั้งหน้าหลังล็อกอิน
- Facebook ไม่ส่ง event = ยังไม่ได้กรอก Callback URL — ดูจาก Vercel log ชี้ขาดได้ (ไม่มี POST เข้า `/api/webhook/facebook` เลย)
- ปุ่ม "ขอคุยเอง" ใช้ไม่ได้จนกว่าเพจจะตั้ง Primary/Secondary Receiver (error `#27`) — ตั้งแล้วหายทันที ไม่ต้อง deploy ใหม่
- วงจร handoff ครบวงยืนยันแล้วจาก log: pass → ตอบใน Business Suite ได้ → take → ตอบจากหน้าแอดมิน → release → บอตกลับมา

## ผ่านการสอบทาน (red-team) แล้ว 1 รอบ
เจอ **6 blocker** ที่เทสต์จับไม่ได้ (เพราะเทสต์ปลอมชั้นฐานข้อมูลกับชั้นโมเดลทับทั้งก้อน) — แก้ครบแล้ว
รายละเอียดทุกข้อ + ข้อที่จงใจเลื่อน อยู่ใน [REDTEAM-FIXES.md](REDTEAM-FIXES.md)

ตัวที่ร้ายที่สุด: การค้นหาใช้ `similarity()` เทียบคำถามสั้นกับเนื้อหายาว ซึ่งได้คะแนน ~0.03 เสมอ
แปลว่า **บอตจะโยนหาคนเกือบ 100% ของคำถาม** — เปลี่ยนมาใช้ `word_similarity()` แล้ว

## หลักฐานว่าใช้งานได้จริง (ไม่ใช่แค่บิลด์ผ่าน)

**ผ่านหน้าเว็บจริงในเบราว์เซอร์:** ล็อกอิน → หน้าภาพรวมขึ้น (เมนู 7 หัวข้อ + ปุ่มสลับสว่าง/มืด) → หน้ากติกา →
พิมพ์ "ขอคุยกับคนหน่อยครับ" ในช่องทดลอง → ระบบตอบถูกว่า *"ถูกจับเป็นคำสั่งพิเศษ (handoff) ซึ่งมาก่อนกติกาทุกข้อ"*

**ยิงทดสอบระดับ HTTP** ด้วยค่าปลอมในเครื่อง:

| ทดสอบ | ผล |
|---|---|
| `/api/health` | `{"status":"พร้อมใช้งาน","missing":[]}` |
| ยืนยัน webhook (token ถูก) | คืน challenge กลับถูกต้อง |
| ยืนยัน webhook (token ผิด) | HTTP 403 |
| POST webhook ไม่มีลายเซ็น | HTTP 401 ไม่ประมวลผล |
| POST webhook ลายเซ็นถูก | HTTP 200 `EVENT_RECEIVED` |
| เข้า `/admin` ไม่ล็อกอิน | 307 เด้งไป `/admin/login` |
| เรียก API แอดมินไม่ล็อกอิน | `{"error":"ยังไม่ได้เข้าสู่ระบบ"}` |
| ล็อกอินผิดรหัส | `{"error":"รหัสผ่านไม่ถูกต้อง"}` |
| ล็อกอินถูกรหัส → เข้าหน้าแอดมิน | HTTP 200 |
| ฐานข้อมูลล่ม (จำลอง) | เซิร์ฟเวอร์ไม่ตาย · log แค่สาเหตุ ไม่มีข้อความลูกค้าหลุด |

`npm run build` ผ่าน (28 route) · `npm test` **80 เทสต์เขียว** · `npm run typecheck` สะอาด

**สิ่งที่ยังพิสูจน์ไม่ได้จนกว่าจะมีฐานข้อมูลจริงและเพจจริง** — ห้ามนับว่า "เสร็จ" ก่อนทำ:
- หน้าแชทที่มีข้อความจริงแสดงผล
- คุณภาพการค้นหาหลังแก้ (ต้องลองด้วยข้อความจริงที่คนไทยพิมพ์ 20 ประโยค แล้วนั่งอ่านผลทีละข้อ)
- การโอนสายกับ Page Inbox ของจริง
→ เดินตารางทดสอบใน [DEPLOY.md](DEPLOY.md) ขั้นที่ 7 ให้ครบทั้ง 8 แถว

## gotchas ที่ต้องรู้ก่อนแตะโค้ด
0. **ถ้อยคำที่บอตส่งในโฟลว์แอดอยู่ใน `lib/qualifier.ts` (SCRIPT = คำต่อคำจากสคริปต์ต้น · EXTRA = เขียนเพิ่ม)** — ห้ามให้โมเดลแต่งข้อความหาลูกค้า · แก้สคริปต์ต้นแล้วต้องตามมาแก้ SCRIPT
0b. ราคาคอร์สอยู่ใน `lib/courses.ts` — ต้นแก้ MASTER แล้ว `npm test` บนเครื่องต้นจะแดงจนกว่าจะแก้ตาม (ตั้งใจ)
0d. ข้อความถึงลูกค้าที่บอตพูดเองต้องมาจาก `SCRIPT`/`VOICE` ใน `lib/qualifier.ts` เท่านั้น — เทสต์ตรวจคำต้องห้าม/"ทีมงาน"/เคสยานยนต์
0e. ร่างตามรอบ 2 ห้ามมีโค้ดเส้นไหนส่งออก (หลัง 24 ชม. Meta ให้ส่งเฉพาะข้อความที่คนพิมพ์)
0c. ข้อความ `sender=system` (สรุปผู้สนใจมีเบอร์) ถูกตัดออกจากประวัติที่ส่งเข้าโมเดล — อย่าเอาออก
1. **แก้โค้ดที่กระทบพฤติกรรม ต้องไล่แก้ `docs/SPEC.md` ใน commit เดียวกัน**
2. webhook ต้องอ่าน **raw body** ก่อน parse ไม่งั้นลายเซ็นไม่ตรง
3. งานหนักอยู่ใน `after()` เพราะต้องตอบ 200 ให้ Facebook ไว ไม่งั้นมันยิงซ้ำ
4. กันซ้ำใช้ unique constraint ในตาราง `webhook_events` ไม่ใช่ตัวแปรในหน่วยความจำ (Vercel มีหลายอินสแตนซ์)
