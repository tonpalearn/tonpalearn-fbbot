สาม

ส่งต่อให้คนจริง

ถ้าลูกค้าขอคุยกับคน หรือบอตตอบไม่ได้ ระบบโอนแชทเข้ากล่องข้อความของเพจ แล้วบอตเงียบสนิทจนกว่าจะกดคืนสาย

สิ่งที่ไม่ทำในรอบนี้

  • ตอบคอมเมนต์ใต้โพสต์อัตโนมัติ — ตอบพลาดต่อหน้าสาธารณะเสียหายกว่าตอบพลาดในแชท (ยกไปเฟส 2)
  • ขายต่อเป็นระบบหลายเพจ — เตรียมโครงฐานข้อมูลไว้แล้ว แต่ยังไม่ทำระบบสมาชิก/บิล
  • รับชำระเงินในแชท — ยังส่งลิงก์ไปหน้าจองของ tonpalearn.com เหมือนเดิม
  • วิเคราะห์รูปที่ลูกค้าส่งมา — ต้นทุนกับความซับซ้อนไม่คุ้มปริมาณตอนนี้
  • แปลหลายภาษาอัตโนมัติ — ลูกค้าจริงเกือบทั้งหมดเป็นคนไทย

ตรวจหาจุดแตกก่อนขึ้นจริง (red-team)ยังไม่เริ่มต้องผ่านก่อน deploy

คำตอบเรื่อง ราคา · วันอบรม · เงื่อนไข ยังเป็นช่องว่างในระบบ (ขึ้นต้นด้วยคำว่า [กรอกเอง]) — ตั้งใจให้เป็นแบบนั้น เพราะระบบถูกออกแบบไม่ให้เดาตัวเลขเอง ตราบใดที่ยังไม่กรอก บอตจะโยนคำถามพวกนี้ให้คนตอบทุกครั้ง

เป้าหมาย (Goals)

รหัสเป้าหมายวัดยังไง
G1ตอบคำถามที่ถามบ่อยได้เองโดยไม่ต้องรอคนอย่างน้อย 60% ของข้อความที่บอตส่งออก มาจากกติกา/คำถามที่ถามบ่อย ภายใน 30 วัน
G2ไม่ปล่อยให้คนสนใจหลุดมืออย่างน้อย 30% ของบทสนทนาที่เข้าข่ายสนใจ จบด้วยการมีชื่อ + ช่องทางติดต่อในระบบ
G3เวลาตอบครั้งแรกสั้นลงค่ากลางของเวลาตอบครั้งแรก น้อยกว่า 10 วินาที
G4ไม่ทำให้ความน่าเชื่อถือเสียจำนวนครั้งที่บอตตอบผิดข้อเท็จจริงจนแอดมินต้องตามแก้ = 0 ครั้ง/เดือน

สิ่งที่ตั้งใจไม่ทำ (Non-Goals)

ไม่ทำอะไรทำไมถึงตัดออก
ตอบคอมเมนต์ใต้โพสต์อัตโนมัติต้องขอสิทธิ์เพิ่มจากเฟซบุ๊ก และตอบพลาดต่อหน้าสาธารณะเสียหายกว่าตอบพลาดในแชท → เฟส 2
ขายต่อเป็นระบบหลายเพจ (SaaS)ใส่ช่องแยกเพจไว้ในฐานข้อมูลแล้ว แต่ระบบสมาชิก/เก็บเงินไม่คุ้มจะทำในรอบนี้
รับชำระเงินในแชทเส้นทางเดิมผ่านหน้าจองของเว็บใช้ได้อยู่แล้ว ไม่มีเหตุให้เพิ่มความเสี่ยง
วิเคราะห์รูปที่ลูกค้าส่งมาต้นทุนกับความซับซ้อนไม่คุ้มปริมาณตอนนี้
แปลหลายภาษาอัตโนมัติลูกค้าจริงเกือบทั้งหมดเป็นคนไทย

คนที่เราออกแบบให้ (Personas)

P1

ผู้สนใจรายบุคคล

คนทำงานที่เห็นโพสต์แล้วอยากเรียน AI

ต้องการ: รู้ราคา วันอบรม และวิธีสมัคร เร็ว ๆ

กลัว: ทักไปแล้วเงียบ หรือโดนขายแบบกดดัน

P2

ผู้ติดต่อองค์กร

ฝ่ายบุคคลหรือหัวหน้าแผนกที่อยากจ้างไปสอนในบริษัท

ต้องการ: รู้ว่ารับจัดในองค์กรไหม และขอใบเสนอราคา

กลัว: ต้องอธิบายเรื่องเดิมซ้ำหลายรอบกับหลายคน

P3

แอดมินเพจ

ต้น หรือผู้ช่วย

ต้องการ: เห็นว่ามีใครทักบ้าง และแทรกเข้าไปคุยเองได้ทันที

กลัว: บอตตอบมั่วแทนตัวเอง หรือไม่รู้ว่าบอตตอบอะไรไป

เรื่องเล่าการใช้งาน (User Stories)

#ใครอยากทำอะไร เพื่ออะไร
1P1ได้คำตอบเรื่องราคาทันทีที่ถาม เพื่อตัดสินใจโดยไม่ต้องรอ
2P1เห็นตัวเลือกเป็นปุ่มกด เพื่อไม่ต้องคิดเองว่าจะถามอะไรดี
3P1ฝากความสนใจไว้แล้วให้ทีมงานติดต่อกลับ เพื่อไม่ต้องเฝ้าแชท
4P2รู้ว่ารับจัดอบรมในองค์กรไหม เพื่อประเมินว่าคุยต่อได้หรือเปล่า
5P2ฝากชื่อบริษัทและเบอร์ไว้ เพื่อให้ทีมส่งใบเสนอราคามาให้
6P3เห็นทุกบทสนทนาในที่เดียว เพื่อไม่พลาดคนสำคัญ
7P3กดปุ่มเดียวแล้วเข้าไปคุยเอง เพื่อรับช่วงต่อจากบอตได้ทันที
8P3รู้ว่าคำตอบแต่ละอันบอตเอามาจากไหน เพื่อไล่แก้ต้นตอเมื่อตอบไม่ดี
9P3แก้คำถามที่ถามบ่อยเองได้ เพื่อไม่ต้องรอโปรแกรมเมอร์

เคสขอบที่ต้องรองรับ

สถานการณ์พฤติกรรมที่ต้องเป็น
บอตไม่รู้คำตอบเสนอส่งต่อให้คน ไม่เดา ไม่แต่งข้อมูล
ลูกค้าโกรธ / ขอคุยกับคนโอนสายทันที และบอตเงียบสนิทหลังจากนั้น
ส่งรูป สติกเกอร์ หรือไฟล์ โดยไม่มีข้อความตอบรับว่าได้รับแล้ว และชวนพิมพ์บอกว่าต้องการอะไร
พิมพ์นอกเรื่องสิ้นเชิงไม่มีเนื้อหาอ้างอิงให้ตอบ → โยนหาคน ไม่เรียกโมเดลให้เปลืองเงิน
เฟซบุ๊กยิงข้อความเดิมซ้ำประมวลผลครั้งเดียว ห้ามตอบลูกค้าซ้ำ
คำตอบยาวเกิน 2,000 ตัวอักษรตัดเป็นหลายข้อความ โดยพยายามตัดที่ช่องว่างหรือขึ้นบรรทัดใหม่
ข้อความมีคำสั่งหลอกโมเดล เช่น "ลืมกติกาเดิม"ถือเป็นข้อความธรรมดา — คำสั่งของระบบห้ามทำตามคำสั่งที่แทรกมา
แอดมินตอบหลังเลย 24 ชั่วโมงลองส่งด้วยสิทธิ์ "เจ้าหน้าที่ติดต่อกลับ" และถ้าไม่ผ่าน ต้องอธิบายสาเหตุเป็นภาษาคน

ข้อกำหนด (Requirements)

P0 = ไม่มีไม่ขึ้นระบบ · P1 = ตามมาเร็ว ๆ นี้ · P2 = เผื่ออนาคต ออกแบบรองรับแล้วแต่ยังไม่สร้าง

P0 — ไม่มีไม่ขึ้น

รหัสเรื่องต้องเป็นจริงว่า
FR-01ยืนยันการเชื่อมต่อเมื่อเฟซบุ๊กมาขอยืนยันช่องทางรับข้อความ ถ้ารหัสยืนยันตรงต้องตอบรับ ถ้าไม่ตรงต้องปฏิเสธ
FR-02ตรวจลายเซ็นทุกข้อความทุกข้อความขาเข้าต้องพิสูจน์ได้ว่ามาจากเฟซบุ๊กจริง ถ้าลายเซ็นไม่ตรง ห้ามประมวลผลใด ๆ ทั้งสิ้น
FR-03ตอบเฟซบุ๊กให้ไวรับแล้วต้องตอบรับกลับทันที แล้วค่อยทำงานหนักต่อเบื้องหลัง ห้ามให้เฟซบุ๊กรอจนหมดเวลา
FR-04กันประมวลผลซ้ำถ้าข้อความเดิมถูกส่งมาอีกครั้ง ต้องข้ามทันที โดยบังคับที่ระดับฐานข้อมูล ไม่ใช่แค่จำไว้ในหน่วยความจำ
FR-05บอตเงียบเมื่อคนคุยถ้าคนกำลังคุยอยู่ หรือปิดสวิตช์บอตไว้ บอตต้องไม่ส่งอะไรออกไปเลย แต่ยังบันทึกข้อความและตั้งธง "ยังไม่ได้อ่าน"
FR-06คำสั่งพิเศษมาก่อนถ้าลูกค้าพิมพ์ "คุยกับคน" หรือ "ขอแอดมิน" ต้องโอนสายทันที แม้จะมีกติกาอื่นที่ตรงกว่า
FR-07กติกาคำสำคัญถ้าข้อความตรงกติกาที่แอดมินตั้งไว้ ให้ทำตามกติกาลำดับต้นสุด และห้ามลงไปเรียกโมเดล — กติกาที่เขียนผิดต้องไม่ทำให้ระบบล้ม
FR-08คำถามที่ถามบ่อยถ้าค้นเจอคำถามที่คล้ายพอและคำตอบกรอกจริงแล้ว ให้ตอบตรง ๆ โดยไม่เรียกโมเดล
FR-09ฐานความรู้ + โมเดลโมเดลตอบได้เฉพาะจากเนื้อหาที่ส่งไปให้เท่านั้น ถ้าข้อมูลไม่พอต้องบอกว่าตอบไม่ได้แล้วโยนหาคน — ห้ามแต่งราคา วันเวลา จำนวน หรือเงื่อนไขขึ้นเองเด็ดขาด
FR-10เพดานค่าใช้จ่ายเมื่อเรียกโมเดลครบจำนวนที่ตั้งไว้ต่อวัน ห้ามเรียกเพิ่ม ให้โยนหาคนแทน
FR-11เก็บข้อมูลทีละขั้นถามทีละอย่าง ชื่อ → ช่องทางติดต่อ → ความสนใจ · ขออนุญาตก่อนถามข้อแรกและบันทึกเวลาที่ยินยอม · เบอร์/อีเมลไม่ถูกรูปแบบให้ถามซ้ำ · ลูกค้าปฏิเสธเมื่อไรให้หยุดทันทีและไม่บันทึกอะไร
FR-12โอนสายและคืนสายโอนแชทเข้ากล่องข้อความของเพจพร้อมบันทึกประวัติ และเมื่อเฟซบุ๊กคืนสายกลับมา ต้องกลับเป็นบอตดูแลอัตโนมัติ
FR-13หน้าผู้ดูแลล็อกอินแล้วต้องทำได้ครบ: ดูภาพรวม · อ่านทุกบทสนทนา · พิมพ์ตอบเอง · ขอคุยเอง/คืนให้บอต · แก้คำถามที่ถามบ่อย · แก้กติกา · เพิ่มฐานความรู้ · ดูและส่งออกรายชื่อผู้สนใจ · แก้ข้อความระบบ · เปิด-ปิดบอตทั้งเพจ
FR-14ความเป็นส่วนตัวฐานข้อมูลปิดจากภายนอกทุกตาราง · ห้ามบันทึกเนื้อหาข้อความลูกค้าลงบันทึกระบบ · ต้องแจ้งขออนุญาตก่อนเก็บชื่อ/เบอร์

P1 — ตามมาเร็ว ๆ นี้

รหัสเรื่อง
FR-15แจ้งเตือนแอดมินเมื่อมีผู้สนใจใหม่ (ผ่าน LINE หรืออีเมล)
FR-16ค้นหาข้อความย้อนหลังในหน้ากล่องข้อความ
FR-17รายงานสรุปรายสัปดาห์ส่งอัตโนมัติ
FR-18บันทึกคำถามที่บอตตอบไม่ได้ ไว้ให้แอดมินกดสร้างเป็นคำถามที่ถามบ่อยได้ทันที

P2 — เผื่ออนาคต

รหัสเรื่องเตรียมอะไรไว้แล้ว
FR-19ตอบคอมเมนต์ใต้โพสต์ แล้วส่งข้อความส่วนตัวต่อยังไม่มี ต้องขอสิทธิ์เพิ่มจากเฟซบุ๊ก
FR-20ดูแลหลายเพจในระบบเดียวทุกตารางมีช่องแยกเพจแล้ว

F1 — ยืนยันการเชื่อมต่อครั้งแรก (ทำครั้งเดียวตอนติดตั้ง)

แสดงภาพไม่ได้ (โหลดตัววาดไดอะแกรมไม่สำเร็จ) — กด "ดูเป็นข้อความ" ด้านล่างครับ

sequenceDiagram
  participant A as แอดมิน
  participant FB as Facebook
  participant S as ระบบเรา
  A->>FB: กรอกที่อยู่ระบบ + รหัสยืนยัน
  FB->>S: ขอยืนยันพร้อมรหัสและคำท้า
  S->>S: เทียบรหัสกับค่าที่ตั้งไว้

    S-->>FB: ตอบรับพร้อมคำท้าเดิม

  else ไม่ตรง
    S-->>FB: ปฏิเสธ

  end
ดูเป็นข้อความ
1. แอดมิน   -> Facebook : กรอกที่อยู่ระบบ + รหัสยืนยัน
2. Facebook -> ระบบเรา  : ขอยืนยันพร้อมรหัสและคำท้า
3. ระบบเรา            : เทียบรหัสกับค่าที่ตั้งไว้
   ถ้าตรงกัน  : ระบบเรา -> Facebook ตอบรับพร้อมคำท้าเดิม -> แอดมินเห็น "เชื่อมต่อสำเร็จ"
   ถ้าไม่ตรง : ระบบเรา -> Facebook ปฏิเสธ -> แอดมินเห็น "ตั้งค่าไม่สำเร็จ"

เกิดอะไรขึ้นตามลำดับ: ตอนติดตั้ง แอดมินบอกเฟซบุ๊กว่าจะส่งข้อความมาที่ไหน พร้อมรหัสลับที่ตั้งเอง เฟซบุ๊กจะยิงมาถามก่อนหนึ่งครั้งเพื่อพิสูจน์ว่าเจ้าของระบบรู้รหัสนั้นจริง ถ้ารหัสตรงกันจะเชื่อมต่อสำเร็จและใช้ตลอดไป ถ้าไม่ตรงจะตั้งค่าไม่ผ่าน — ทำครั้งเดียวจบ

F3 — ถามอิสระ ต้องค้นฐานความรู้

แสดงภาพไม่ได้ (โหลดตัววาดไดอะแกรมไม่สำเร็จ) — กด "ดูเป็นข้อความ" ด้านล่างครับ

sequenceDiagram
  participant L as ลูกค้า
  participant S as ระบบเรา
  participant DB as ฐานข้อมูล
  participant AI as โมเดล AI
  L->>S: "เรียนออนไลน์ได้ไหม มีอัดวิดีโอย้อนหลังไหม"
  S->>DB: ไม่มีกติกาตรง จึงค้นคำถามที่ถามบ่อย
  DB-->>S: คะแนนความคล้ายต่ำกว่าเกณฑ์
  S->>DB: ตรวจเพดานการใช้โมเดลวันนี้
  DB-->>S: ยังไม่ถึงเพดาน
  S->>DB: ค้นฐานความรู้
  DB-->>S: ได้เนื้อหา 3 ท่อนที่ผ่านเกณฑ์
  S->>AI: คำสั่งห้ามแต่งข้อมูล + เนื้อหาอ้างอิง + คำถาม
  alt ข้อมูลพอ
    AI-->>S: คำตอบที่อ้างเฉพาะเนื้อหาที่ให้
    S->>L: ตอบลูกค้า
    S->>DB: บันทึกที่มา "ฐานความรู้ + AI"
  else ข้อมูลไม่พอ
    AI-->>S: ตอบไม่ได้
    S->>L: "ขอส่งต่อให้ทีมงานนะครับ"
    S->>DB: โอนสาย + บันทึกประวัติ
  end
ดูเป็นข้อความ
1. ลูกค้า -> ระบบเรา : "เรียนออนไลน์ได้ไหม มีอัดวิดีโอย้อนหลังไหม"
2. ระบบเรา -> ฐานข้อมูล : ไม่มีกติกาตรง จึงค้นคำถามที่ถามบ่อย
3. ฐานข้อมูล -> ระบบเรา : คะแนนความคล้ายต่ำกว่าเกณฑ์
4. ระบบเรา -> ฐานข้อมูล : ตรวจเพดานการใช้โมเดลวันนี้ -> ยังไม่ถึงเพดาน
5. ระบบเรา -> ฐานข้อมูล : ค้นฐานความรู้ -> ได้เนื้อหา 3 ท่อนที่ผ่านเกณฑ์
6. ระบบเรา -> โมเดล AI : คำสั่งห้ามแต่งข้อมูล + เนื้อหาอ้างอิง + คำถาม
   ถ้าข้อมูลพอ    : โมเดลตอบโดยอ้างเฉพาะเนื้อหาที่ให้ -> ตอบลูกค้า -> บันทึกที่มา "ฐานความรู้ + AI"
   ถ้าข้อมูลไม่พอ : โมเดลบอก "ตอบไม่ได้" -> ระบบบอกลูกค้าว่าขอส่งต่อให้ทีมงาน -> โอนสาย + บันทึกประวัติ

เกิดอะไรขึ้นตามลำดับ: คำถามนี้ไม่ตรงกติกาและไม่เหมือนคำถามที่ถามบ่อยพอ ระบบจึงเช็กก่อนว่าวันนี้ใช้โมเดลเกินเพดานหรือยัง แล้วค้นเนื้อหาที่เกี่ยวข้องจากฐานความรู้ส่งให้โมเดลเรียบเรียง จุดสำคัญคือโมเดลถูกล็อกไว้ให้ตอบได้เฉพาะจากเนื้อหาที่ส่งไปเท่านั้น ถ้าข้อมูลไม่พอ มันต้องบอกว่าตอบไม่ได้ แล้วระบบจะโยนให้คน ไม่ใช่เดาไปเรื่อย

เสร็จสิ่งที่ต้องส่งทำไมต้องมีเจ้าของ
รหัสลับของแอปเฟซบุ๊ก และรหัสยืนยันที่ตั้งเองใช้พิสูจน์ว่าข้อความที่เข้ามาเป็นของเฟซบุ๊กจริง ไม่มีก็รับข้อความไม่ได้เลยต้น

คีย์เรียกโมเดล AIใช้เฉพาะชั้นที่ 6 ตอนต้องเรียบเรียงคำตอบจากฐานความรู้ต้น

ครบทุกข้อนี้เท่านั้นจึงนับว่าส่งมอบแล้ว — ไม่ใช่แค่ "โค้ดรันได้"

เสร็จเกณฑ์
โปรแกรมสร้างผ่าน และเทสต์อัตโนมัติเขียวทั้งหมด
เชื่อมต่อกับเฟซบุ๊กสำเร็จ และตรวจลายเซ็นของจริงผ่าน
ส่งข้อความทดสอบเข้าเพจแล้วบอตตอบกลับได้จริง โดยมีหลักฐานเป็นภาพหรือบันทึก
หน้าผู้ดูแลเปิดได้ ล็อกอินได้ แก้คำถามที่ถามบ่อยแล้วบอตตอบตามที่แก้จริง
โอนหาคนแล้วบอตเงียบจริง และคืนสายกลับมาได้
สเปกและ PRD ฉบับนี้ตรงกับโค้ดที่ส่ง
มีคู่มือขึ้นระบบที่คนอื่นทำตามแล้วขึ้นได้เอง
ผ่านการตรวจหาจุดแตกก่อนขึ้นจริง และแก้ประเด็นระดับ blocker ครบ

ก้าวถัดไปที่ชัดที่สุด

  1. ต้น — อ่านเอกสารนี้แล้วบอกว่าตรงกับที่คิดไว้ไหม โดยเฉพาะส่วน D หน้าจอจำลอง
  2. ต้น — ตอบคำถามค้าง Q2 (ราคา/รอบอบรม) และ Q4 (บุคลิกบอต) เพราะสองข้อนี้บล็อกการเปิดใช้จริง
  3. ทีมพัฒนา — ปิดหน้าผู้ดูแลให้ครบและตรวจด้วยตาจริงทุกหน้า
  4. ผู้ตรวจ — ไล่หาจุดแตกก่อน deploy แล้วแก้ให้ครบ
  5. ทั้งทีม — เปิดใช้ในวงจำกัดก่อน (แอดมินเพจทดสอบเอง) แล้วค่อยเปิดให้คนนอก
