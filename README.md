# FB Page Chatbot — TONPALEARN

ผู้ช่วยตอบแชท Facebook Page ที่ตอบคำถามซ้ำ ๆ ได้เองตลอด 24 ชั่วโมง เก็บข้อมูลคนที่สนใจไว้ให้ และโอนสายให้คนจริงเมื่อเกินกำลัง

## สมองของบอตทำงานยังไง

ตัดสินใจเป็นชั้น ๆ จากถูกที่สุดไปแพงที่สุด — ชั้นบนตอบได้ก็ไม่ลงไปชั้นล่าง

| ชั้น | ทำอะไร | ค่าใช้จ่าย |
|---|---|---|
| 0 | กันข้อความซ้ำ (Facebook ยิงซ้ำได้) | – |
| 1 | ถ้าคนกำลังคุยอยู่ บอตเงียบสนิท | – |
| 2 | คำสั่งพิเศษ: "คุยกับคน" / "เมนู" / "หยุดบอต" | – |
| 3 | กำลังเก็บข้อมูลผู้สนใจ → ถามขั้นต่อไป | – |
| 4 | กติกาคำสำคัญที่แอดมินตั้งเอง | – |
| 5 | คำถามที่ถามบ่อย (จับคู่ด้วยความคล้ายของตัวอักษร) | ค้นในฐานข้อมูล |
| 6 | ค้นฐานความรู้แล้วให้ Gemini เรียบเรียง | เรียกโมเดล (มีเพดานต่อวัน) |
| 7 | ตอบไม่ได้ → เสนอส่งต่อให้คน | – |

**กฎเหล็ก:** โมเดลตอบได้เฉพาะจากเนื้อหาที่ค้นเจอเท่านั้น ห้ามแต่งราคา วันเวลา หรือเงื่อนไขขึ้นเอง — ถ้าข้อมูลไม่พอ ให้โยนหาคนแทนการเดา

## เริ่มใช้งาน

```bash
npm install
cp .env.example .env.local   # แล้วกรอกค่าจริง
npm run dev                  # เปิด http://localhost:3111
```

## คำสั่งที่ใช้บ่อย

```bash
npm test                     # เทสต์ตรรกะการจับคู่ + ตรวจลายเซ็น
```

## โครงไฟล์

```
app/
  api/webhook/facebook/   รับ event จาก Facebook
  api/admin/              API ของหน้าผู้ดูแล
  admin/                  หน้าผู้ดูแล
lib/
  brain.ts                สมองไฮบริด 7 ชั้น
  matching.ts             ตรรกะจับคู่ (ฟังก์ชันบริสุทธิ์ เทสต์ครบ)
  facebook.ts             ตัวเชื่อม Messenger Platform
  ai.ts                   เรียก Gemini แบบล็อกให้อ้างเฉพาะเนื้อหาที่ค้นเจอ
  store.ts                ทุกการคุยกับฐานข้อมูล
supabase/migrations/      โครงตาราง + ข้อมูลตั้งต้น
```

## ข้อควรระวัง

- `SUPABASE_SERVICE_ROLE_KEY` ใช้ฝั่งเซิร์ฟเวอร์เท่านั้น หลุดไปฝั่งเบราว์เซอร์ = เปิดฐานข้อมูลทั้งใบ
- ทุกตารางเปิด RLS และไม่ให้สิทธิ์ anon เลย — เข้าถึงได้ผ่านเซิร์ฟเวอร์ของเราทางเดียว
- ไม่ log ข้อความของลูกค้าลง console (PDPA)
- คำตอบที่ยังขึ้นต้นด้วย `[กรอกเอง]` บอตจะไม่เอาไปตอบ — ต้องกรอกของจริงก่อนเปิดใช้
